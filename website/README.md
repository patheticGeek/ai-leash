# ai-leash docs site

A [Nextra](https://nextra.site) site, deployed to GitHub Pages by
[`.github/workflows/docs.yml`](../.github/workflows/docs.yml) on every
push to `master` that touches `README.md`, `docs/**`, or `website/**`.

```bash
npm install
npm run dev    # http://localhost:3000
npm run build  # static export to out/
```

## Content is generated, not hand-written

Everything under `src/content/` **except the two `_meta.js` files** is
generated by `scripts/sync-docs.mjs`, which runs automatically before
`dev`/`build`:

- `src/content/index.mdx` ← the repo root `README.md`
- `src/content/docs/features/*.mdx` ← `docs/features/*.md`

This is deliberate — the docs site should never drift from the real
docs, so there's exactly one source of truth. Don't edit anything under
`src/content/` besides the two `_meta.js` files (they control sidebar
ordering/labels, which isn't derivable from the content itself); it'll
just get overwritten on the next build. The generated files are
gitignored for the same reason.

The sync script also escapes raw `<`/`{` outside of code spans (Rust
generics like `` Vec<PathBuf> `` and event-name templates like
`` chat://{sessionId}/... `` are common throughout `docs/features/`) since
MDX would otherwise try to parse them as JSX/expressions — and rewrites
the source docs' relative markdown links into site routes (or, for links
to non-doc repo files, into `github.com/.../blob/master/...` URLs, since
the docs site doesn't serve those files).

## The `zod` override in `package.json`

Pinned to `4.3.6` to work around a real upstream bug: `nextra-theme-docs`
4.6.x's `Layout` component fails Zod validation on every page
(`Invalid input: expected nonoptional, received undefined → at children`)
once `zod` resolves to 4.4.x or later — see
[shuding/nextra#5008](https://github.com/shuding/nextra/issues/5008).
Confirmed by bisecting down to the most minimal possible content tree
(a single `index.mdx`, no nesting) and still hitting the same error, so
it's not anything specific to how this site's content is structured.
Safe to remove this override once that issue is fixed upstream.
